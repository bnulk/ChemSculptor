# Skill 与 Workflow 编写指导书

本指导书规定 ChemSculptor 中 Skill 与 Workflow 的判断方法、职责边界、建设模板和验收规则。
它适用于新增任务、重构既有任务，以及接入新的计算程序或客户端入口。

强制要求：

```text
Skill 做一件事。
Workflow 驱动一件事完成。
Skill 是能力单元，Workflow 是编排单元。
```

判断标准以行为和依赖为准，不以类名、文件名或目录位置为准。

## 1. 先判断该写 Skill 还是 Workflow

### 1.1 Skill 的判据

满足以下条件的工作应写成 Skill：

```text
完成一个边界清楚、可重复调用的能力。
输入、输出、失败语义和成功证据可以冻结。
只负责一次正常执行及其直接结果。
不自行决定重试、修复、审批或最终归档策略。
可以通过公共接口被不同 Workflow 复用。
```

典型例子：

```text
生成并执行一次单点计算。
从一份输出读取优化轨迹。
执行一次波函数稳定性检查。
按给定状态号计算 NTO。
解析一次振动分析结果。
```

### 1.2 Workflow 的判据

出现以下任一要求时，应编写 Workflow：

```text
需要顺序、并行、条件分支或循环。
需要判断异常并决定是否恢复。
需要派生多个作业尝试并保留历史。
需要汇总多个 Skill 的产物。
需要跨阶段持久化状态与证据。
需要对用户提供阶段进度、最终结果或可下载成果包。
```

典型例子：

```text
优化、稳定性检查、振动分析和恢复的完整编排。
TDDFT、NTO 选择与 NTO 计算的连续编排。
吸收光谱的多阶段编排。
全过程档案包和科学点归档。
```

### 1.3 不可混淆的边界

```text
Skill 不负责“整件事最终是否完成”。
Workflow 不负责“科学计算细节本身”。
Skill 可以有结果验证，但不能把失败自动解释成完整恢复计划。
Workflow 可以调用能力，但不能绕过能力接口直接复制科学算法。
```

若一个模块既要执行科学计算，又要决定重试、派生作业、汇总结果和控制客户端流程，
该模块已经越界，必须拆成 Skill、Workflow 和公共执行设施。

## 2. 两类 Skill

### 2.1 运行时 Skill

运行时 Skill 是实际执行的 C# 能力，负责输入校验、调用适配器、读取结果和返回契约。
建议结构：

```text
接口负责契约
薄基类负责生命周期
密封具体类负责科学逻辑
执行器负责调度和持久化
```

具体实现应保持密封，除项目现有框架明确要求外，不使用可继承的开放继承体系。

### 2.2 Codex Skill

Codex Skill 位于：

```text
.agents/skills/<skill-name>/SKILL.md
```

它说明 Codex 在什么条件下选择该任务、使用哪个运行时入口、应遵守哪些边界，
不复制运行时代码，也不承担科学结果计算。

Codex Skill 与运行时 Skill 必须能通过名称、能力 ID 和文档互相定位。

### 2.3 任务级 Skill 说明

每个任务级 Skill 还必须提供：

```text
docs/skill说明/<skill-id>.md
```

说明文件至少逐项写出：

```text
目标
输入与输出契约
参数和默认值
程序翻译
结果解析
验证规则
异常码
恢复边界
所属 Workflow
Agent、API 与客户端接入
测试和验收证据
关联文件
```

如果 Codex Skill 和运行时 Skill 不是一对一，说明文件必须明确对应关系。

## 3. 薄抽象基类的边界

允许薄基类统一：

```text
上下文检查
输入校验的公共骨架
计时
取消传播
公共异常转换
结果封装
证据回调
通用日志
```

禁止薄基类包含：

```text
某个程序的路由规则
SCF 修复规则
优化恢复规则
TDDFT 状态筛选规则
NTO 选择规则
某任务的数据库字段解释
某任务专用的条件分支
```

薄基类应通过接口、装饰器或公共上下文接入横切能力。
不得因为一个任务需要新状态，就迫使所有已有 Skill 修改基类。

## 4. 依赖与任务独立性

### 4.1 允许的依赖方向

```text
Skill -> 公共契约、程序适配器接口、仓储、公共基础设施
Workflow -> Skill 调用接口、执行器、证据仓储、公共策略接口
执行器 -> 通用 Skill 契约和通用状态模型
```

### 4.2 禁止的依赖方向

```text
具体 Skill 直接引用另一个具体 Skill 实现。
具体 Skill 直接引用 Workflow。
Workflow 直接引用具体 Skill 实现类。
Workflow 直接调用另一个具体 Workflow 实现。
通用执行器写任务专用分支。
公共模型携带只有某一个任务才使用的科学规则。
```

跨任务复用必须经过：

```text
能力 ID
通用 Skill 调用接口
公共契约
公共能力注册表
```

### 4.3 新增任务的独立性验收

新增一个任务原则上只应：

```text
新增任务模块及其契约、实现和测试。
新增依赖注入注册。
新增该任务对应的文档和 Codex Skill。
必要时增加通用能力实现，但不改变已有任务行为。
```

以下现象必须视为设计问题：

```text
新增任务时修改了另一个任务的主体实现。
新增任务时修改多个已有 Workflow 才能编译。
新增任务时在通用执行器中增加该任务专用 if/switch。
新增任务时让已有测试大面积按新任务字段改写。
新增任务时必须改变公共结果模型才能表达自身结果。
```

共享上下文和横切基础设施应通过统一上下文、接口或装饰器接入，
不应继续把跨任务逻辑散落到各任务实现中。

## 5. 状态、证据与恢复

状态必须使用稳定枚举或稳定字符串，不得靠自然语言推断。
建议统一状态：

```text
Ready
Running
Completed
Failed
Canceled
Skipped
```

恢复必须满足：

```text
新建作业尝试，不覆盖原作业。
记录 ParentJobId。
记录 AttemptNumber。
记录 RootWorkflowId。
记录触发异常和修正参数。
保存恢复前后的验证证据。
保留失败、取消和跳过历史。
```

证据至少应能回答：

```text
执行了哪个阶段和哪个作业。
使用了哪些参数及其来源。
读取了哪些输入和输出。
产生了哪些验证结果。
为何发生恢复。
恢复是否重新验证并通过。
```

不得用“最终科学点文件”替代全过程证据。
科学点集合是计算阶段的标准化结果，不是过程档案本身。

## 6. 错误码与分支规则

Workflow 必须基于稳定错误码分支，不能匹配自然语言句子。
错误码示例：

```text
scf.not_converged
output.missing
energy.missing
optimization.not_converged
frequency.imaginary_mode
wavefunction.unstable
nto.source_missing
```

每个错误码必须具有：

```text
稳定 ID
严重级别
所属层次（程序、任务、Workflow）
可检查证据
允许的恢复动作
面向用户的安全摘要
```

异常检查应返回结构化证据，不应只返回一段日志文本。
恢复规划只能消费已登记的异常和证据。

## 7. 程序与任务隔离

通用层不得出现程序专有输入、输出和控制逻辑，例如：

```text
Gaussian
g16
.gjf
%chk
SCF Done
Normal termination
GAUSS_EXEDIR
ORCA
```

程序规则只能留在命名的适配边界：

```text
ProgramParameterTranslator
ProgramInputWriter
ProgramOutputParser
ProgramAnomalyCheck
ProgramAdapter
```

客户端允许输入程序原始关键词，但服务器必须先将其转换为通用参数，
再由程序翻译器生成实际输入。程序关键词不得原样穿透到任务领域模型。

通用任务结果不得依赖具体输出文件的原始行格式。
原始文本可以作为证据保存，但科学逻辑必须消费结构化结果。

## 8. 11 步强制建设模板

任务级 Skill 和完整 Workflow 默认必须严格按以下 11 步建设：

| 步骤 | Skill 重点 | Workflow 重点 | 最低验收证据 |
|---|---|---|---|
| 1. 契约 | 冻结单次能力输入、输出、成功和失败语义 | 冻结目标、阶段、总结果、停止和取消语义 | 契约测试、JSON 往返 |
| 2. 参数 | 定义该能力所需规范参数和默认值 | 定义跨阶段参数、覆盖规则和来源 | 提取、覆盖、非法参数测试 |
| 3. 翻译 | 调用程序翻译边界，不把程序语法带入通用层 | 确保各阶段使用一致参数和程序选择 | 翻译快照测试 |
| 4. 结果 | 产出结构化单次结果和证据 | 汇总阶段结果、最终采用结果和产物索引 | 解析与聚合测试 |
| 5. 执行 | 执行一次正常任务 | 顺序、并行、分支和阶段调度 | 正常路径集成测试 |
| 6. 验证 | 验证本能力必需结果 | 汇总验证并决定继续、恢复或停止 | 正常与缺失证据测试 |
| 7. 异常 | 报告本能力稳定错误码 | 归并异常并选择分支 | 每个错误码测试 |
| 8. 恢复 | 只声明恢复边界和所需证据 | 诊断、规划、派生作业、执行和复检 | 恢复链测试 |
| 9. 工作流 | 说明可被哪些 Workflow 使用，不反向依赖 | 定义 DAG、分支、上限、停止、确认和归档 | 全分支测试 |
| 10. 接入 | 注册能力 ID 和调用入口 | 接入 Agent、API、客户端、Codex Skill | 集成测试 |
| 11. 测试 | 单元、契约、集成和取消测试 | 正常、分支、恢复、重启和证据测试 | 可复现测试记录 |

每一步都必须有明确代码落点或文档落点，并有对应测试或验收证据。

原子能力 Skill 可以使用以下子集：

```text
契约 -> 执行 -> 验证 -> 测试
```

即使使用子集，也必须明确说明为何不需要其他步骤。

特殊情况不能遵循模板时：

```text
1. 先在设计文档中说明原因。
2. 说明影响范围和替代方案。
3. 说明如何保证安全、可测试和可追溯。
4. 必须由用户确认后再开始实现。
5. 在 CHANGES.md 中记录例外。
```

禁止静默省略步骤。

## 9. 测试矩阵

### 9.1 Skill 最低测试

```text
正常输入返回预期结果。
缺参返回明确错误。
非法参数被拒绝。
正常终结和异常终结均可区分。
结果缺失不会产生伪造成功。
错误码稳定。
Serialize/Deserialize 往返不丢字段。
取消能够传播且不写成功状态。
重复执行不会污染前一次结果。
```

### 9.2 Workflow 最低测试

```text
正常路径完成并归档。
每个条件分支至少覆盖一次。
异常诊断和恢复路径可达。
恢复作业通过 ParentJobId 关联。
恢复后执行复检。
跳过条件能记录 Skipped 及原因。
程序硬失败会中止并返回明确错误。
服务重启后可从持久化状态继续或安全终止。
不覆盖历史作业和证据。
全过程证据登记完整。
```

## 10. 实现与评审清单

开始编码前：

```text
已判断是 Skill、Workflow 还是两者组合。
已冻结契约和稳定错误码。
已列出代码落点、文档落点和验收证据。
已确认不会修改其他任务主体实现。
```

提交评审前：

```text
具体 Skill 不引用具体 Skill。
Workflow 不引用具体 Skill 实现或另一个具体 Workflow。
通用层没有程序专有逻辑。
状态、证据、恢复和错误码均有测试。
任务级说明文件已更新。
Codex Skill 与运行时入口一致。
未按模板的部分已有书面确认。
```

## 11. 最终压缩规则

> 先判型，再定契约；正常能力放 Skill，目标编排放 Workflow；具体任务密封实现，公共规则交给薄基类和执行器；跨任务只通过能力接口，不通过具体类。

新增任务原则上只新增模块、依赖注入注册和测试，不修改已有任务实现。
共享上下文和横切基础设施应通过统一上下文、接口或装饰器接入，不继续散落到各任务。
